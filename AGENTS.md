# AGENTS.md

Guidance for AI agents (and humans in a hurry) working on Stamp Studio.

## Project

Postage stamp studio: Vite + React + TypeScript + Tailwind CSS v4 +
shadcn/ui + three.js. Static build, deployed on Vercel (auto-deploys on push
to `main`).

- `src/lib/stamp-texture.ts` - the 2D bake: paper stock, foxing and wear,
  frame and lettering, artwork re-separation per press, postmark, and the
  perforation signed distance field. Returns an albedo canvas whose alpha is
  the silhouette, plus an aux canvas (R = ink coverage, G = edge distance)
- `src/lib/stamp-renderer.ts` - the 3D side: paper GLSL shader, intaglio
  relief, gummed back, curl geometry, PNG/GIF/video/GLB exporters
- `src/lib/settings.ts` - `StampSettings` interface, defaults, format aspects
- `src/lib/fonts.ts` - the lettering faces and the loader the bake waits on
- `src/lib/ornaments.ts` - corner ornaments as SVG path data, tinted on bake
- `src/lib/presets.ts` - the looks offered in the sidebar's "Start from"
- `src/lib/analytics.ts` - OpenPanel, production only, keyed by
  `VITE_OPENPANEL_CLIENT_ID`
- `src/components/Sidebar.tsx` - props editor
- `src/components/StampCanvas.tsx` - main canvas + render loop
- `src/App.tsx` - state, upload, export orchestration, toolbar, dialogs
- `CHANGELOG.md` - generated by changesets; rendered by the in-app
  "What's new" dialog (`src/lib/changelog.ts` parses it at build time)

## Rules

1. Every user-facing change MUST include a changeset. Run `npx changeset`
   (or add a file under `.changeset/`) with a `minor` bump for features and
   `patch` for fixes. CI opens a "Version Packages" PR that bumps
   `package.json` and `CHANGELOG.md` - never edit those two by hand.
2. Do not hand-edit `CHANGELOG.md`. The in-app changelog dialog parses its
   changesets format (`## <version>` + bullets).
3. Verify before committing: `npx tsc -b` and `npm run build` must pass.
4. Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`, `style:`).
5. No AI attribution in commits, PRs, or code comments.
6. Match existing conventions: Tailwind utilities (no new styling systems),
   oklch for any new color values, shadcn/ui primitives from
   `src/components/ui/`.
7. Anything expensive belongs in the bake, not the per-pixel JS loop. The
   loop in `buildStampMaps` runs on every settings change, so fibre,
   watermark and lighting live in the shader where they stay crisp at export
   size. Keep it that way.
8. Canvas text falls back silently when a webfont has not arrived. Any new
   face MUST be added to `loadStampFonts` in `src/lib/fonts.ts`, which the
   canvas awaits before re-baking.
9. Secrets never enter the repo. The OpenPanel client id is public and lives
   in `VITE_OPENPANEL_CLIENT_ID`; the client secret is server-side only and
   belongs nowhere in `src/`.
10. Shader, bake or geometry changes need a visual check in the browser
    (`npm run dev`): the perforated edge at low and high gauge, an aged
    sheet, a struck postmark, the corner lift, and a PNG export.

## Commands

```sh
npm run dev        # dev server
npx tsc -b         # typecheck
npm run build      # production build
npx changeset      # record a change (required for features/fixes)
```
